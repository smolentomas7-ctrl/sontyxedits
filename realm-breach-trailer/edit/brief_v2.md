## TECHNICAL — PRODUCTION METHOD

Method: HYBRID.
- Blender + Python (EEVEE; Cycles only if a shot truly needs it): characters, environments, VFX, all shots.
- Python + librosa: song analysis. PySceneDetect: reference analysis.
- FFmpeg: edit, grade, titles, subtitles, mix, export.
- TTS + procedural audio: voice and sound effects.

Project structure:
realm-breach-trailer/
  input/song/, input/reference/
  config/video.py      → 1080×1920, 30 fps, palette, safe zones, lens presets, seeds
  config/timing.json   → generated from the song; the single source of truth for every shot's timing
  analysis/            → song.json, reference.json, waveform.png
  assets/              → characters/, enemies/, environments/, vfx/, fonts/, audio/, characters.md
  scenes/              → one Blender Python script per shot
  src/                 → analysis, timeline, render, tts, sfx, edit and mix scripts
  build/               → characters/, stills/, shots/, preview/
  edit/                → shot_list.md, timeline.json
  output/
  PROGRESS.md          → updated after every step so the work can resume
  README.md            → how to re-render everything with one command

Rules:
- Never invent song timestamps. Every time position comes from the audio analysis.
- Deterministic rendering: everything is a function of the frame number; every random generator is seeded per shot. The same frame always renders the same way.
- Never spend long render time on anything not yet checked as a still or a low-res preview.
- Title font: download an open-licensed serif display font (e.g. Cinzel from the google/fonts GitHub repository) and note its licence.

Steps:
1. Setup: check Blender (command line), ffmpeg/ffprobe, Python 3. If Blender is missing, stop and tell me how to install it. Install librosa, numpy, soundfile, opencv-python, scenedetect.
2. Song analysis: BPM, beats, downbeats, energy. Find the intro, build-up, drop (D), break, biggest hit (U), outro. Save a waveform PNG with markers, check it, write config/timing.json.
3. Reference analysis: every cut, shot lengths, flashes, cut rate per section.
4. Shot list: write edit/shot_list.md before production. For every shot: act, time (from timing.json), camera, lens, depth of field, motion, subject and action, lighting, transition, audio, and why the shot exists.
5. Characters — CHECKPOINT 1: model the warrior (late and early look) and the Fallen God, render turnarounds (front, side, back, visor close-up), review and fix them, then show me the contact sheet and WAIT for my OK.
6. World and VFX: build reusable assets, then every environment and effect.
7. Reference frames — CHECKPOINT 2: render one vertical key frame per shot, one contact sheet in shot order. Check composition in 9:16, safe zones, lighting, colour and consistency. Fix, then show me the contact sheet and WAIT for my OK.
8. Animate and render every shot natively at 1080×1920, first at 50% resolution for the preview.
9. Voice, sound effects, subtitles, edit, grade, mix.
10. Render a 540×960 preview of the whole video.
11. Review the preview (below), fix everything you find, render the preview again. Repeat until it holds up.
12. Render the final output/realm_breach_trailer.mp4. Verify with ffprobe: 1080×1920, 30 fps, duration, audio stream. If anything fails, diagnose and fix it before finishing.
